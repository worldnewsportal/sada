You are a senior mobile architect, backend engineer, DevOps engineer, security engineer, UI/UX designer, and distributed-systems engineer.

Your task is to build a production-grade mobile messaging application inspired by Telegram, with a modern architecture, scalable backend, CDN-based media delivery, real-time messaging, file sharing, groups, channels, calls-ready architecture, push notifications, authentication, search, caching, and strong security.

IMPORTANT:

- Do NOT create a fake demo.
- Do NOT use mock data for core functionality.
- Do NOT leave major features as TODOs.
- Do NOT build only the UI.
- Every major screen must connect to a real backend/API.
- The application must be structured so it can realistically scale from a small number of users to millions.
- Make sensible engineering decisions instead of asking unnecessary questions.
- If a requirement is ambiguous, choose the most production-appropriate solution and document the decision.
- Prioritize reliability, security, performance, maintainability, and low infrastructure cost.
- Never claim something works unless the implementation actually exists.

- object storage is used for media
- API servers remain stateless where practical
- workers scale according to queue depth
- PostgreSQL is optimized before adding another database

- logs do not grow without limits
