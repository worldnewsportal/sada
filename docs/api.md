# Sada API v1 — Reference (spec §5, §43)

Base URL: `/api/v1` · Auth: session cookie (HttpOnly) or `Authorization: Bearer <access>`
Envelope: `{ok:true,data}` / `{ok:false,error:{code,message,details},requestId}`
Headers on every response: `x-request-id`. OpenAPI machine spec: `/api/v1/openapi.json` shape mirrors this table (generated by `scripts/gen-openapi.ts`).

## websocket protocol (port 3003 via gateway)
- auth: `io(url, {auth:{token}})` — token from `/auth/socket-token` (60s)
- server → client `event`: `{seq, type, chatId?, payload}` — types: MESSAGE_CREATED/UPDATED/DELETED/READ/DELIVERED/REACTION_UPDATED/PINNED, USER_TYPING/ONLINE/OFFLINE, CHAT_UPDATED/PINNED, MEMBER_ADDED/REMOVED, ADMIN_CHANGED, CHANNEL_POSTED, NOTIFICATION_CREATED, CALL_OFFER/ANSWER/ICE/END
- client → server: `typing {chatId,isTyping}` · `delivered {chatId,upToSeq}` · `subscribe {chatIds}` · `call:* {toUserId,…}` (membership-validated)
- reconnect: client exponential backoff → `/sync?since=` reconciliation (§6 of architecture.md)

## Rate limits (defaults — env-tunable)
login 20/min/IP · OTP 3/min/phone · verify 8/min · send 25/10s · uploads 60/min · username 5/day · group 20/h · channel 10/h · search 60/min · default API 300/min → `429` with `retryAfterS`.
